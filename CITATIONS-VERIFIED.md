## NVD primary-source check (2026-10-11, text read by the user from nvd.nist.gov and pasted)

- **CVE-2013-4787**: NVD description confirmed: Android 1.6 Donut through 4.2 Jelly Bean does not properly check cryptographic signatures; an APK modified in a way that does not violate the signature, "probably involving multiple entries in a Zip file with the same name in which one entry is validated but the other entry is installed", aka Android security bug 8219321 and the "Master Key" vulnerability. NVD does not name Bluebox; the Bluebox/Forristal attribution and July 2013 date come from the secondary sources above.
- **CVE-2017-13156**: NVD description is only: "An elevation of privilege vulnerability in the Android system (art). Product: Android. Versions: 5.1.1, 6.0, 6.0.1, 7.0, 7.1.1, 7.1.2, 8.0. Android ID A-64211847." CVSS 3.x base score 7.8 HIGH (NIST). **NVD does not use the name "Janus" and does not describe the APK/DEX mechanism.** Cite NVD only for the CVE ID, the affected versions (5.1.1 to 8.0, not "5.0+") and the Android ID; cite the GuardSquare blog (13 Nov 2017) for the name "Janus" and the dual APK/DEX mechanism. The earlier note "affects Android 5.0+" came from press coverage and differs from NVD's list.
- **CVE-2022-30190**: NVD description confirmed: remote code execution when MSDT is called using the URL protocol from a calling application such as Word; arbitrary code with the privileges of the calling application. CVSS 3.1 base 7.8 HIGH, vector AV:L/AC:L/PR:N/UI:R/S:U/C:H/I:H/A:H (NIST and the CNA, Microsoft, agree). The name "Follina" is not in NVD; it comes from the community reports and the MSRC guidance.
