# noxos-os

**Shell + AOSP/Soong** — build pipeline for the AOSP fork. Does not and will never contain the AOSP source itself (250GB+ checkout) — only the `repo` tool local-manifest overlay and build automation.

## Layout

| File | Purpose |
|---|---|
| `local_manifests/roomservice.xml` | `repo` local manifest overlay. As of 2026-08-31, clones `noxos-os` itself a second time into `device/noxos/cf_x86_64_phone/` inside the AOSP tree, so the repo-root device-tree files below get picked up as a lunch target. |
| `AndroidProducts.mk` / `noxos_cf_x86_64_phone.mk` / `noxos.rc` | The **v1** device-tree overlay (repo root, not a subdirectory — AOSP's product-config scan only finds `AndroidProducts.mk` exactly two levels under `device/`). Inherits stock `device/google/cuttlefish/vsoc_x86_64_phone.mk`, then trims a small starting `PRODUCT_PACKAGES` list, sets `PRODUCT_LOCALES := en_US`, sets `PRODUCT_DEX_PREOPT_DEFAULT_COMPILER_FILTER := speed`, and copies a trivial `noxos.rc`. **Completely unverified against a real tree** — see `../TASKS.md`'s "v1 device overlay" section for exactly what's confirmed-real vs. best-effort-guessed. |
| `infra/setup-instance.sh` | One-time provisioning: `repo` tool, JDK, AOSP's documented Ubuntu build-dep package list. |
| `infra/sync.sh` | `repo init -u https://android.googlesource.com/platform/manifest -b android-latest-release`, installs the local manifest, `repo sync -c -j$(nproc)`. |
| `infra/build.sh` | `lunch`es Cuttlefish (`LUNCH_TARGET` env var, default `aosp_cf_x86_64_phone-userdebug` = v0) and runs `m dist`. Set `LUNCH_TARGET=noxos_cf_x86_64_phone-userdebug` for the v1 overlay target — no script change needed, it was already overridable. |
| `infra/setup-cuttlefish-local.sh` | Local Cuttlefish host bring-up (Arch laptop, not AWS): builds `cuttlefish-host:latest` from `google/android-cuttlefish`'s `container/image/Containerfile` and runs it privileged with `/dev/kvm`+`/dev/net/tun` passed through. `--prereq-check`/`--build`/`--start`/`--stop`. Verified working — see `CUTTLEFISH.md`. |
| `.github/workflows/build.yml` | `workflow_dispatch`-only, `runs-on: self-hosted`. Not wired to push/PR — no self-hosted runner registered yet. S3 upload step deliberately deferred until AWS lands. |

## AOSP branch

`android-latest-release` — AOSP's officially recommended always-current branch, chosen over pinning a specific tag so the manifest doesn't go stale.

## Branding

`branding/bootanimation.zip` — fade-in loop of the NoxOS mark, generated by `branding/generate-bootanimation.sh` from a vendored copy of `assets/branding/logo-mark.svg` (root repo has the source of truth). Verified: unzipped and inspected the actual frames, real fade-in from 0→100% opacity, not just a script that ran without erroring. **Not wired into any build target** — boot animations get referenced from a device tree (`device/<vendor>/<device>/bootanimation.zip` or similar), which doesn't exist until P3/P4 (lightweight base / device tree work). Revisit then.

## Status (2026-08-31)

**A real `r5.2xlarge` box is up and running `sync.sh` → `build.sh` (v0) → `build.sh` (v1) right now** — see `../TASKS.md`'s Phase 1a for live resource IDs, IP, and the two real bugs found getting it running (Ubuntu 24.04's missing `libncurses5`/`lib32ncurses5-dev` forced a relaunch on 22.04; persistent spot requests hit a stricter quota than one-time ones did). Each build uploads to the now-live `noxos-releases` S3 bucket.

The **v1 device-tree overlay** (`AndroidProducts.mk`/`noxos_cf_x86_64_phone.mk`/`noxos.rc`, plus a boot-animation copy and an accent-color resource overlay added later the same session) is real Make/AOSP product-config code, checked against Google's own documentation, but **has never touched a real AOSP tree before this run** — treat it exactly as unverified as the AVF stub code in `noxos-app`/`noxos-payload` was before Phase 2 confirmed those. This run is that confirmation.

**Local Cuttlefish (Phase 1b) is real and running**, not just planned: `infra/setup-cuttlefish-local.sh` builds and runs a `cuttlefish-host:latest` container (Google's own `container/image/Containerfile`, privileged, `/dev/kvm`+`/dev/net/tun` passed through) — verified live as of this session (`docker ps` shows `cuttlefish_orchestrator` up, orchestrator services running). No AVD instance created inside it yet (`cvd fleet` → empty) since there's no real NoxOS image to boot until Phase 1a produces one. Full detail, including two things that were wrong and got corrected against the real container (no `/home/user`, no standalone `launch_cvd`/`stop_cvd` binary — just a unified `cvd` CLI): `CUTTLEFISH.md`.

The first successful `repo sync` + `m dist` on the AWS box, followed by a proven snapshot/restore cycle **and** a real `cvd create` against that output inside the already-running local container, is the Phase 1a/1b exit criterion — everything else (GMS-strip, jniLibs handoff, Warden priv-app integration) is explicitly gated behind it.
